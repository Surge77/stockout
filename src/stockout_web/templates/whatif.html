What would a shop like this take?

No store id. Describe a shop by its attributes and get a sales estimate for one day — the same way a house-price model works from bedrooms, floor area and location rather than from a house's address.

Why this is a different model from the forecast page

The forecast page answers how much will store 12 take on Monday, and the model it uses is allowed to know that store 12 is store 12 — the store's id is one of its inputs. That model cannot answer this page's question: a shop that does not exist has no id, and there is no honest value to put in that box.

So the artefact carries a second regressor, fitted on every feature except identity and except the two competitor/promotion ages, which nobody describing a new shop could supply. It is scored differently too: it is tested by hiding one shop from the training data completely and then asking about it — which is exactly the situation you are in on this page. {% if unseen_r2 %} It scores {{ '%.3f'|format(unseen_r2) }} on that test, on a scale where 1.00 is perfect and 0.00 is no better than always answering with the average shop. {% endif %}Any other score would be measuring an easier question than the one this page asks.

This only works because what a shop is — its size of range, how close its nearest rival sits, which group it belongs to — genuinely moves how much it sells. When those details carried no real signal, the same test scored −0.70: worse than useless, since simply answering with the average would have beaten it. The page would still have shown a confident number. That is why the score above is on screen rather than buried.

They do not add up to the total, and they are not meant to — a tree ensemble is not additive and these inputs interact. The question answered is what is this attribute doing here.
